# 素材采集分类工具

**独立桌面工具**：从 4 个渠道采集广告素材，用 AI 视觉模型自动分类，并支持定时自动跑。

本工具是从上游主程序里**独立拆出来**的：不依赖上游主程序、不依赖 Java、不依赖数据库，
自带 Electron 壳和精简 Python 运行时，拷贝整个目录到任何 Windows 电脑就能用。

---

## 功能

### 采集（下载中心）
| 渠道 | 说明 |
|---|---|
| 妙思 AdMuse | 按时间范围、行业、跑量得分筛选下载 |
| 有米云 AppGrowing | 关键词搜索，支持广告媒体 / 流量平台 / 素材比例 / 素材类型筛选 |
| 热云 Reyun | 关键词搜索，支持创意类型和排序 |
| 内部系统 | 走账号管家登录态直采，**可指定数据日期**（下载哪一天的表格），支持图片 / 视频模式（视频走 API 直采：产品关键词 + 消耗 Top N） |

> **有米云筛选的一个坑**：「素材类型」是两级结构（父级 视频 / 图片 / 其他，叶子 10 个）。
> 广告视图的默认排序是「按视频播放数降序」，而该视图结果**全是视频卡**；
> 若再把类型筛成图片类（图片 / 图标 / 轮播图 / 组图 / GIF 等），交集为空，页面一条都不返回。
> 脚本现在会自动把这类组合的排序换成「按投放时间降序」并在日志里说明；
> 想筛图片也可以直接把结果类型改成「素材」视图。

### 分类（素材治理）
- **API 极速分类** —— 并发提交视觉模型提取关键词，再由本地规则定产品与方向
- **API 精细分类** —— 低并发、高阈值，适合相似素材复核
- **画面方向拆解** —— 只输出画面方向、构图和视觉钩子
- 不包含 OCR / CLIP 本地模型，不需要 Torch、EasyOCR，只走视觉 API

#### APP 方向清单（2026-09-28 业务侧定调）

APP 业务线的方向**收敛到固定清单**，其余一律归「内容创意」：

| 类别 | 方向 |
|---|---|
| 内容方向（11） | 网赚、萌宠、老歌、旅游、美食、短剧、一分购、官方样式、内容创意、购物、快手电商 |
| 版式方向（3） | 多区块图文、左右图文、上下图文（09-22 从「上下左右图文」细分而来） |
| 衍生标记 | 秒思自动衍生 / 妙思自动衍生 / 妙思衍生（妙思自动衍生素材专用，引擎机制） |

- **APP 下不再有「未知」**：方向判不出来、或落在清单之外，全部落「内容创意」；
  业务线本身认不出（abstain）仍走「待确认」。
- **快手电商**：开店 / 商家入驻 / 流量扶持这类**招商广告**单独成目录，不混进「内容创意」；
  原来的「电商」已并入它，不再单独存在。
- 业务线认不出产品时不受影响；**保险 / 卡券等其他业务线完全不受此清单约束**
  （保险沿用「月亮 / 图标 / 插画 / 上下左右图文 / 宠物 / 大字报 / 朋友圈」）。
- 相关改名：`宠物 → 萌宠`（APP 用萌宠，保险仍用宠物）、`低价好物 → 购物`、
  `电商 → 快手电商`、`0.01元 → 一分购`、`0.1元 → 购物`、`旅游攻略 → 旅游`。
- 两条产出路径都会过这一关：外部平台（妙思/有米云/热云）走 business_line 模式，
  内部系统走 collection_taxonomy 模式（会先被分类表门控，再收敛到清单）。

#### 违规素材拦截（规则可改，不用改代码）

业务侧 2026-09-29：**保险的素材里，画面出现箭头的要单独落到「违规素材」**，
不再按「图标」归档。
业务侧 2026-10-10：**模仿系统界面交互的图**（播放按钮、关闭按钮等）也算违规素材。
这类规则以后还会加，所以做成了配置文件：

**`userdata/violation_rules.json`**（文件不存在会自动生成一份默认的）

```json
{
  "version": 2,
  "rules": [
    {
      "id": "insurance-arrow",
      "name": "保险-箭头素材",
      "enabled": true,
      "business_lines": ["保险"],
      "direction": "违规素材",
      "keywords": ["箭头"],
      "reason": "画面出现箭头，属违规素材",
      "include_uncertain": false
    },
    {
      "id": "ui-mimicry",
      "name": "界面伪装素材",
      "enabled": true,
      "business_lines": [],
      "direction": "违规素材",
      "keywords": ["播放按钮", "关闭按钮", "全屏按钮", "静音按钮", "音量条",
                   "进度条", "返回键", "系统弹窗", "假搜索框", "假输入框",
                   "系统状态栏", "系统导航栏"],
      "match_fields": ["ui_mimicry_elements"],
      "reason": "画面模仿系统/App 界面控件，属违规素材",
      "include_uncertain": false
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `business_lines` | 只在这些业务线生效；**留空数组 = 所有业务线都拦** |
| `keywords` | **按子串匹配** AI 提取到的关键词，写「箭头」就能覆盖「白色向上箭头」「三角箭头图标」等 |
| `direction` | 命中后落到哪个方向（可以改成别的名字） |
| `enabled` | 置 `false` 可临时关掉这条规则 |
| `match_fields` | **只在这些证据字段里匹配**；留空 = 扫全语料（旧规则的行为） |
| `include_uncertain` | 默认 `false`。AI 把箭头写进 `uncertain`（自己标了「含义不明确」）时不算命中；打开后连这些也拦 |

- **改完即时生效**，不用改代码、不用重启（每次跑批重新读文件）。
- 多条规则命中时**按配置顺序取第一条**。
- **违规拦截是最后一关**：优先级高于常规方向判定，两条产出路径都过这一关，
  同一素材不会因为走的平台不同而落到不同方向。
- 命中会写进审计的 `reason`（如「违规拦截：保险-箭头素材：命中「箭头」」），
  方便回溯是规则改的方向。
- 用环境变量 `MATERIAL_DOWNLOADER_VIOLATION_RULES` 可以临时指向别的规则文件（调试用）。

> **为什么默认不拦 `uncertain`**：实测 25 张含箭头的保险素材里，有 1 张箭头只出现在
> `uncertain`（AI 自己写的是「小型箭头状图标，来源与含义不明确」）。默认不拦是避免误伤，
> 需要全拦就把该规则的 `include_uncertain` 改成 `true`（实测会从 24 张变 25 张）。

##### 界面伪装素材（2026-10-10）

「模仿系统界面交互」指的是**伪装成播放器/浏览器/手机系统的控件、让用户误以为能点**的元素：
假的播放按钮、角落的 ×、模拟视频进度条、模拟「内存不足/权限申请/立即清理」弹窗、
模拟手机状态栏或底部导航栏。命中后落 `业务线/产品/违规素材`。

**为什么这条规则必须写 `match_fields`**：这些词在正常素材里也会出现，实测 1114 条里就有

- `绿色弧形进度条` —— 装饰弧线（月亮素材）
- `播放按钮图标` —— 红果短剧 / 腾讯动漫的**品牌 Logo**
- `八个圆点按钮` —— 权益装饰（154 条）
- `静音滑轮` —— 行李箱的**商品卖点文案**

扫全语料会把这些全判成违规。所以：AI 侧新增一个专门字段 `ui_mimicry_elements`，
提示词里明确要求它只填「伪装成系统控件的元素」，并**写死排除项**（品牌 Logo 内部的图形、
权益列表项图标、装饰性圆点、商品功能文案、广告自身的行动按钮）；
规则侧用 `match_fields` 只在这个字段里匹配 —— 双保险，零误伤。

> **生效条件**：`ui_mimicry_elements` 是新增字段，**旧素材缓存里没有它**，
> 所以已经分类过的批次不会命中这条规则（行为与改动前完全一致，已回归验证）。
> **要让它开始起作用，需要用新提示词重新跑一次批次。**

`check_rules.py` 的 **C7** 会静态校验这份配置：字段名拼错、没有关键词、没有落点方向
都会报出来 —— 这类错误否则是**完全静默**的（规则看着正常，永远不命中、不报错）。

##### 违禁元素素材（2026-10-10）

国旗、国徽等**涉政国家象征**与**涉黄低俗内容**也算违规素材，落同一个「违规素材」方向。
业务侧特别强调：**插画类尤其要注意**（卡通、动漫、Q 版、手绘风格最容易被整体忽略）。

用的还是同一套两层机制：AI 侧字段 `prohibited_elements`，规则侧 `match_fields` 限定。

受控值（模型只能从这些里选）：

| 类别 | 值 |
|---|---|
| 涉政 | 国旗、国徽、党徽、国家领导人形象、人民币图案、军旗军徽、国家机关标识 |
| 涉黄 | 色情裸露、性暗示、低俗挑逗 |

**为什么也要限定字段**：`国` 字在正常素材里太常见（「25元/月，热门国漫随心看」），
品牌角标也常被误认；`人民币` 还可能是权益列表里的 **¥ 符号图标**。扫全语料会误伤。

**提示词里写明的判断边界**（避免误伤，命中任一条就写 `[]`）：

- 品牌与企业标识（淘宝、快手、QQ阅读的角标/Logo），即使配色相近也不算
- 几何或装饰性图形，仅形状相似但非明确可辨的国家象征不算
- 正常人物着装（连衣裙、运动服、泳装、亲子装等生活场景）不算
- 普通文字里的「国」「党」等字（如「国漫」「国民好物」）不构成违禁元素

> **为什么提示词要专门写「这是广告发布前的合规审查、只做事实记录」**：
> 模型对涉政涉黄内容有**回避倾向**，可能干脆不描述、或用极模糊的说法，导致规则空转。
> 提示词因此明确要求客观中立记录、并要求卡通/Q版风格同样判断。

> ⚠️ **这一项尚未用真实样本验证过**：两批 1114 条素材里没有国旗/涉黄内容，
> 已实测确认的是「模型愿意输出这个字段」（正常图返回 `[]`，未拒答）。
> **有真实素材时请先用几张跑一遍**，确认模型是否肯如实填 ——
> 这是当前唯一没被验证的环节。

### 自动化计划（本工具新增）
- 每条计划 = **一个渠道 + 一套筛选参数 + 执行时间 + 星期**
- 到点自动执行，并**接着把下载下来的素材分类完**（一条龙），无需人工守着
- 可单独关闭某条计划的自动分类，只下载不整理
- 执行时间相同的多条计划会**排队依次执行**，不会同时抢账号管家
- **采集与分类走两条独立车道，可以同时进行**（详见下节）

#### 怎么新增一个「内部系统视频」采集任务

内部系统的图片与视频是**两条独立的计划**（计划带「素材类型」字段），做法：

1. 「自动化计划」页 → **＋ 新建计划**
2. 平台选 **内部系统**
3. **素材类型**选 **视频**（这一步决定产出落到 `日期/视频/`，且**只下载不分类**）
4. 填 **产品关键词**（如 `保险`）和 **消耗 Top N**（默认 50）——这两个只对视频模式生效
5. 设执行时间与星期 → 保存

产出：`内部系统/YYYYMMDD/视频/原始素材/`，同时 `报表/` 里带一份 `capture-items.json`。
视频**不进分类流程**，所以不会有 `分类结果` 目录，运行历史里也会写明「视频模式只下载不分类」。

> 图片计划照旧（素材类型=图片），产出在 `内部系统/YYYYMMDD/图片/`。
> 两者可以设同一时间，会按队列依次跑，互不干扰。

#### 按日期下载内部系统的表格（补采 / 回溯）

内部系统的「数据日期」可以自己选，不用再靠「昨天」：

| 入口 | 怎么用 |
|---|---|
| **下载中心 → 内部系统** | 「数据日期」默认昨天，可选任意历史日期；快捷按钮「昨天 / 前天 / 一周前」。启动导出即按该日期查询 |
| **自动化计划 → 平台参数（内部系统）** | 「数据日期」留空 = 跟随运行日（日常定时任务不变）；填了 = 每次执行都下载这一天，适合补采 |

**产出目录口径**：内部系统的目录名是**运行日**，装的是前一天的表格，所以
**目录 = 数据日期 + 1 天**。选 `2026-10-12` → 落到 `内部系统/20261013/图片/原始素材`，
与日常定时任务（13 号早上导出 12 号数据）的目录完全一致，补采不会散落在今天的新目录里。
选到今天或未来时目录回落到今天，不会生成还没到的目录。

- 查询日期会写进任务日志（`[日期] 数据日期 …`）和运行历史（`查询 …`），事后能核对采的是哪天。
- 脚本侧本来就有这道闸：查询后读表格「日期」列，与期望日期不符会**主动中止**，避免采错整天。
- 手动导出固定走「图片」分支，产出结构与定时计划一致（`日期/图片/…`）。

### 任务队列：采集 / 分类 双车道

队列分成两条**互不阻塞**的车道，各自内部串行：

| 车道 | 跑什么 | 为什么这样 |
|---|---|---|
| **采集** | 各渠道下载 | 共用账号管家的浏览器登录态，必须串行，否则会互相抢标签页 |
| **分类** | API 极速/精细分类、方向拆解 | 纯视觉 API 调用，不碰浏览器，可以和采集同时跑 |

于是「下载 + 分类」一条龙不再独占队列：**下载一结束就释放采集车道**，
分类转到分类车道继续跑，采集车道立刻能接下一条计划。
多条同时间的计划因此可以连续开跑，不用等前一条分类完。

分类车道不并行、只串行，是因为脚本自身已开 10 路 API 并发，
两条分类叠加会把网关压垮（实测并发 16 反而比 10 更慢）。

「自动化计划」页顶部的队列条会分别列出两条车道的运行中 / 等待任务，
两条车道同时跑时队列条会变色，一眼能看出是并行而不是卡住。

### 运行历史（本工具新增）
- 每次运行都留一条记录：时间、触发方式、状态、下载张数、分类结果、耗时
- 完整日志落盘在 `userdata/logs/`，界面里可直接查看、复制、打开目录

## 快速开始

### 1. 前置条件：启动账号管家
采集靠复用「账号管家」（`onion.exe`）里的浏览器登录态，**日常不接触账号密码**。
动手前请：

1. 打开账号管家 `onion.exe`
2. 确认调试端口 **9223** 已开启
3. 在账号管家里登录好要采集的平台（妙思 / 有米云 / 热云 / 内部系统）

端口没开或没登录，下载脚本会连不上，任务会直接失败——这是失败原因里最常见的一条。

#### 妙思掉线会自动补登录（可选，需配凭据）

妙思的登录态偶尔会掉。脚本检测到未登录时会**自动用 QQ 账号密码补一次登录**
（最多 3 次），省得人工盯着。它按下面的顺序找凭据，**找到第一个就用**：

| 顺序 | 位置 |
|---|---|
| 1 | 环境变量 `ADMUSE_QQ_USERNAME` + `ADMUSE_QQ_PASSWORD`（或 `ADMUSE_QQ_CREDENTIALS_FILE` 指向文件） |
| 2 | 本工具目录 `userdata/admuse_qq_credentials.txt` ← **想自己指定就放这里，最直观** |
| 3 | 从脚本往上逐级找 `data/shared/material_collections/妙思/账号密码.txt` |
| 4 | 兄弟工程 `sibling_workspace_a/`、`sibling_workspace_b/` 下的同名文件 |

凭据文件格式是**两行纯文本**，第一行账号、第二行密码：

```text
your-account
your-password
```

- **凭据永远不会写进日志**，日志里只会出现「凭据来自本地凭据文件」这类说明。
- 找不到凭据时会明确打印 `LOGIN_STATUS|NO_CREDENTIAL`，并在界面上显示
  「未找到 QQ 账号密码，无法自动补登录」——**不会静默跳过**。
- QQ 登录可能触发**手机验证**，那种情况脚本没法替你完成，界面会提示
  「等待恢复登录态或手机验证」，需要人工处理一次。

### 2. 启动工具

双击 **`创建桌面快捷方式.bat`**（只需一次），桌面会出现「素材采集分类工具」图标。
以后双击图标即可静默启动，没有黑窗。

| 启动方式 | 用途 |
|---|---|
| 桌面图标 / `启动-无窗口.vbs` | 日常使用，无黑窗 |
| `启动.bat` | 排错用，能看到启动日志和报错 |

> **定时计划要求工具一直开着。** 调度器跑在应用进程内，关掉窗口就不再触发。
> 想让它按时自动采集，就让它留在后台别关。

### 3. 配一次 API
进「素材治理」页，在右下角填 **API Endpoint / Model ID / API Key**，点保存。
必须是**支持看图的视觉模型**。配置存在 `userdata/classify_config.json`，只需要配一次。

> 仓库里只带一份脱敏模板 `userdata/classify_config.example.json`。
> 首次运行前把它复制成 `userdata/classify_config.json` 再填自己的地址与密钥；
> 真实配置文件已被 `.gitignore` 排除，不会被误提交。

### 4. 开始用

- **手动跑一次**：在「下载中心」选渠道 → 填条件 → 启动下载
- **定时自动跑**：在「自动化计划」页 → `＋ 新建计划` → 设时间和星期 → 保存

## 自动化计划怎么配

每条计划包含四块：

**基础** —— 计划名称、采集平台、执行时间（HH:mm）、每周执行日、下载根目录、最大下载数。

**平台参数** —— 按所选平台显示对应的筛选条件（关键词、时间范围、行业、素材比例、排序等）。
内部系统走登录态直采，参数通过环境变量传入，界面上只需要选图片/视频。

**一条龙** —— 勾选「下载完成后自动执行 API 分类」后，下载成功会自动接上分类；
可设并发数、最低置信度、复制/移动模式。

**几个行为约定**
- 星期一个都不选会自动按「每天」处理，不会出现"没选日子却乱跑"
- 同一分钟只触发一次，30 秒轮询不会重复排任务
- 下载完一张图都没有时，**跳过分类**，避免白跑一次 API 调用
- 下载成功但分类失败，记录为「部分完成」，素材仍然保留
- 计划存在 `userdata/capture_plans.json`，可以直接手工编辑

## 输出目录结构

四个渠道共用同一套结构。**同一天、同一平台只用一个日期目录**——
同一平台一天会按不同方向采集多次（如 保险 / APP），这些采集都并进同一个日期目录，
产品在「分类结果」下自然分成多个子目录：

```text
导出根目录/
└── 平台/                        # 妙思 / 有米云 / 热云 / 内部系统
    └── YYYYMMDD/                # 当天所有采集共用这一个目录
        ├── 原始素材/            # 下载下来的图（多次采集累加，重复的会跳过）
        ├── 报表/                # 采集日志、Excel 报表、媒体映射（按次合并，不覆盖）
        └── 分类结果/            # 一条龙分类的产物
            ├── 保险/            # 一级分类（产品）
            │   ├── 插画/        # 二级分类（方向）
            │   │   ├── 横版/    # 按图片真实尺寸分横竖
            │   │   └── 竖版/
            │   └── 图标/横版/
            ├── APP/卡券/插画/竖版/
            ├── _待确认/竖版/     # 置信度不足，等人复核
            ├── _API分类审计.jsonl        # 逐张审计记录（追加式，可断点续跑）
            └── _API分类调试审计.xlsx
```

**方向下再按横竖分一层**：判定用图片真实像素，`宽度 ≥ 高度 → 横版`，`高度 > 宽度 → 竖版`
（方图归横版，不单列），口径与上游 2026-09-01 的横竖版重分类一致。
因此**每个叶子目录的父目录必为 `横版` 或 `竖版`**，下游按横竖取件时不用猜层级。
读不出尺寸的图片按横版兜底，不会因为异常丢件。

### 内部系统：日期下再分「图片 / 视频」

内部系统的计划带**素材类型**（图片 / 视频），两种模式的产物结构不同，
所以只有内部系统在日期下多一层：

```text
内部系统/YYYYMMDD/
├── 图片/                        # 图片模式：下载 + 分类
│   ├── 原始素材/
│   ├── 报表/
│   └── 分类结果/                # 产品/方向/横版|竖版
└── 视频/                        # 视频模式：只下载，不分类
    ├── 原始素材/
    └── 报表/                    # 没有分类结果目录
```

- **视频只下载不分类**：视频不进视觉关键词分类流程（提示词、审计、目录层级都是为图片设计的）。
- 图片与视频**共用同一个日期目录**，各自独立的 `原始素材 / 报表`（视频没有 `分类结果`）。
- **其他平台不受影响**，仍是 `平台/日期/原始素材`。

合并是安全的，因为：

- **下载**按文件名/URL 跳过已存在的素材，重复采集不会重复下载、也不会产生重复文件
- **分类审计**（`_API分类审计.jsonl`）是追加式且带断点续跑，已处理过的会跳过
- **清单与映射**（`capture-items.json`、`media-map.json`）按次**合并**写入，不会互相覆盖

运行历史里会分别显示「本次新增」和「当天共 N」两个数，避免把累计量误读成本次下载量。

- 内部系统的 Excel 报表进 `报表`，从报表下载的图进 `原始素材`
- 下载完成后，整理页的目录框会自动定位到本次批次，方便手动补跑分类

### 改完代码怎么验证

双击 **`自检.bat`**，它会用工具自带的 Electron 当 Node 运行时，检查 49 项核心逻辑：
调度判定（时间命中、星期匹配、停用跳过、防重复触发）、计划参数归一化与夹取、
各平台 CLI 参数拼装、下载进度解析。

自检**只跑纯逻辑**，不联网、不碰账号管家，也不读写你的计划与历史文件。

### 业务目录从哪来（策略中心）

分类用的「业务线-产品-方向」**不是本地手写的**，而是从**策略中心的目录**同步生成的：

```bash
PY=classify-engine/runtime/python/python.exe
$PY classify-engine/tools/sync_taxonomy.py            # 只对比，不改文件
$PY classify-engine/tools/sync_taxonomy.py --apply    # 写回分类表
```

- 策略中心（`your-taxonomy-host.example.com`）是业务目录的**唯一权威来源**：业务线、产品、方向都按它来，
  落盘目录名也是它的名字（例：内部叫「QQ阅读」，输出是策略中心的「QQ阅读-25元」）。
- `scripts/taxonomy_overrides.json` 只登记**本地例外**，三类：产品别名、
  策略中心暂未建但素材里真实存在的产品、以及同理的方向。每条都写了原因。
- **注意**：策略中心的方向列表 ≈「已经建过策略的方向」，不是封闭词表。
  所以本地已用、策略中心未建的方向要显式登记，否则会被门控成「未知」。

#### 怎么新增一个产品（示例）

以「保险」业务线下新增一个产品（下称**示例产品A**）为例。**四处都要改，漏一处就静默失效**：

| # | 位置 | 作用 |
|---|---|---|
| 1 | `scripts/taxonomy_overrides.json` → `extra_products` | 策略中心暂未建的产品，登记后同步时会叠加进分类表（否则整条被门控成「未知」） |
| 2 | `collection_taxonomy_v1.json` → `products` | 让**当前**就能用（改完 overrides 要重跑同步才会写进去；同步不通时手工补） |
| 3 | `PRODUCT_BUSINESS_LINES` + `PRODUCT_DIRECTIONS` | 产品归属哪条业务线、允许哪些方向 |
| 4 | `PRODUCT_RULES` **和** `LEGACY_PRODUCT_RULES` | 判定词表——**两张表都要**，见下面那个坑 |

> ⚠️ **最大的坑：产品判定分两阶段。** `LEGACY_PRODUCT_RULES` 是**第一阶段**
> （历史稳定规则），只有它拒绝才轮到 `PRODUCT_RULES`。
> 示例产品A 最初只加进新表，实测 280 条**只判对 16 条**——第一阶段就被同业务线的
> 另一个宽泛产品抢走了。两张表都要加，并且要在对方的 `negative` 里
> 加上示例产品A 的专属词让它让位。

**关键词别拍脑袋**，要从真实证据统计里取。做法：把已采素材的审计结果按 `brand_keywords`
聚合计数，挑高频且互斥的词进词表。示例产品A 的证据分布长这样：

```
示例产品A  品牌全称                 452 次   品牌英文缩写 示例产品A   339 次
示例产品A                           150 次   品牌英文缩写+Logo     38 次
合作方品牌名 + 示例产品A 联合推出       38 次   示例产品A 文字/Logo   33/20 次
```

`compact_text` 会转小写去空格，所以写 `("<品牌英文缩写>", 16)` 就能覆盖
带空格、带 Logo 后缀等各种写法。

**重叠产品靠正负分让位。** 示例产品A 的主打险种和另一个宽泛产品同名，280 条里
254 条同时含该险种名——所以必须给那个宽泛产品加负向词：

| 素材 | 示例产品A 得分 | 宽泛产品得分 | 结果 |
|---|---|---|---|
| 典型示例产品A（含品牌缩写 + slogan） | **74** | -24 | 示例产品A |
| 示例产品A Logo、无文字 | **42** | -36 | 示例产品A |
| 普通宽泛产品素材 | 0 | **52** | 宽泛产品 |
| 只提到母品牌 | 6（<阈值 9） | 0 | 不误判 |

**验证方式**：改完拿真实审计跑一遍，两侧都要看——

```bash
# 示例产品A 素材应全部判成示例产品A；其他保险素材不应有误入的
$PY -m unittest tests.test_product_rules -v
```

关注两个数：**自身召回**（该产品是否全判对）和**误入率**（其他产品是否被误判进来）。
两条产出路径（外部平台 / 内部系统）都要跑，结果应一致。

### 规则怎么自检

改分类规则（分类表、证据词、方向词表）**先双击 `规则自检.bat`**。它跑三件事：

**① 一致性校验** —— 不跑分类，只检查规则本身是否自洽，能发现三类静默故障：

- **两套词表的方向差集**：内部词表能产出的方向、对外分类表却不允许
  → 命中就会被门控成「未知」。这是最容易踩的坑，规则会把自己算对的答案擦掉。
- **七处表的产品同步**：加一个产品要同时改七张表，漏一处就 KeyError 或产品识别不出来。
- **别名与证据词**：指向不存在方向的死别名、同表内权重冲突、空词。
- **方向判据覆盖**：分类表里声明了、但证据表/别名链/代码谓词里**都没有判据**的方向
  → 命中的素材 100% 落「未知」。这类是「建了方向、忘了写规则」，
  和死词表同源。同步策略中心后会自动报出新出现的这类方向。

有 ERROR 时退出码非 0，可以直接挂到 CI 上。

**② 健康报告**（把审计 jsonl 拖到 `规则自检.bat` 上，或直接调 `rule_health.py`）
读 `分类结果/_API分类审计.jsonl`，自动给出：

- **门控归因**：哪些方向本来识别出来了、却被门控成未知（带条数排序）
- **零命中词**：规则表里哪些证据词在这批素材里一次都没命中
- **新方向候选**：模型给出、但不在任何产品允许集里的方向及出现次数
  —— 这是判断「现有方向不够用」的客观依据

**③ 改规则前后对比**（`replay_audit.py`）用已存的审计证据离线重跑规则，
**不调 API、不动缓存**，几秒内给出全局影响：

```bash
PY=classify-engine/runtime/python/python.exe
$PY classify-engine/tools/replay_audit.py --audit "审计.jsonl" --dump before.json
#   ……改规则……
$PY classify-engine/tools/replay_audit.py --audit "审计.jsonl" --dump after.json --compare before.json
```

**④ 命名依赖度体检**（`ablation_filename.py`）回答「API 拆出来的视觉证据本身够不够用」：
同一份审计证据跑两遍，唯一变量是**要不要给文件名**，差额就是靠命名兜底的量。

```bash
$PY classify-engine/tools/ablation_filename.py --audit "审计.jsonl" --source "原始素材" --platform internal
```

原则是**命名只能参考、不能拿它归类**。实测 1114 条：去掉文件名后产品落未知
2.2%→7.4%、方向 5.9%→10.2%，即视觉证据独立支撑了 92.6% 的产品判定。

**⑤ 按新规则重跑历史批次**（`replay_batches.sh`）—— 规则改完，想把历史素材也按新规则整理：

```bash
bash classify-engine/tools/replay_batches.sh              # 重跑所有历史批次
bash classify-engine/tools/replay_batches.sh 20260927     # 只试跑某个批次名
```

- **不调 API**：只重放已有审计，分钟级完成。
- **不动原数据**：产出到各批次的 `分类结果-新规则/`，原 `分类结果/` 一字不改。
- 审计里 API 失败、没有视觉证据的少数几张会**跳过并逐批报告**，不会卡死整批。
- 跑完用 `compare_replay.py` 看新旧差异、用 `validate_replay_output.py` 校验产出结构。

> ⚠️ **重放路径必须和线上路径一致**。曾经踩过：重放无条件套分类表门控，
> 而主流程只对内部系统套（外部平台走 `business_line` 模式不套），
> 结果保险的「上下左右图文/宠物/朋友圈」被凭空打成「未知」，
> 对比里出现 38% 的假变化。判断信号：**大面积、方向不明的迁移，
> 先怀疑重放工具跑偏，而不是规则变化**。

**⑥ 汇总月度合集**（`survey_collection.py` + `aggregate_collection.py`）

把多个平台一个月的素材汇总成一份**去重**的合集，再分类。三步：

```bash
PY=classify-engine/runtime/python/python.exe
SHARE='\\fileserver\share\素材汇总'             # 平台目录的上一级

# ① 盘点：图片数 + MD5 重复（只读，大目录比较慢）
$PY classify-engine/tools/survey_collection.py --share "$SHARE" --month 202609

# ② 汇总去重（默认只预演，确认后加 --apply）
$PY classify-engine/tools/aggregate_collection.py \
      --survey classify-engine/tools/_survey.json --output "$SHARE\..\9月合集"

# ③ 合并各批次审计 → 重放（不调 API）
$PY classify-engine/tools/merge_audits_for_collection.py \
      --collection "$SHARE\..\9月合集" --share "$SHARE"
$PY classify-engine/scripts/replay_audit_rules.py \
      --source "$SHARE\..\9月合集\原始素材" \
      --audit  "$SHARE\..\9月合集\_合集审计.jsonl" \
      --output "$SHARE\..\9月合集\分类结果" \
      --config userdata/classify_config.json --platform admuse
```

实测 9 月四平台：44,635 张 → **去重后 17,171 张（砍掉 61.5%）**，
重复主因是同一张图被连续多天重复采集（有个 MD5 出现 112 次）。

**关于「按产品分」的坑**：合集混了多个平台时**不要**用 `--platform internal`。
「按产品分」要求先认出具体产品，外部平台的图认不出会把**整条业务线**一起丢成「待确认」
（实测 32.1% vs 按业务线分的 12.1%）。合集统一用外部平台参数（如 `admuse`）。

**缺证据的怎么办**：重放只处理审计里**有证据**的条目，其余会跳过并报数。
补它们就再跑一次正常分类（断点续跑会自动只处理缺的）：

```bash
$PY classify-engine/scripts/classify_pure_api.py \
      --source "$SHARE\..\9月合集\原始素材" --output "$SHARE\..\9月合集\分类结果" \
      --config userdata/classify_config.json --platform admuse --parallel 10
```

> ⚠️ **抽样 ≠ 全量**。9 月那次抽样两个批次都说"100% 有证据"，
> 全量一跑发现 30% 缺证据（429 限流 / 密钥无效 / 无文本）。
> 做规模判断必须全量核对，否则会低估 API 成本。
掉下去的那些（红果短剧、淘宝联盟、短剧）就是**该补视觉证据、而不是继续靠命名**的地方。

> ⚠️ 重放用的是**旧证据**。如果改动涉及提示词（模型输出的字段变了），
> 重放结果会失真——必须拿原图重新抽一次证据才算验证。

## 常见问题

**下载失败 / 一直连不上？**
先查账号管家：`onion.exe` 是否在跑、9223 端口是否开、对应平台是否已登录。
在「启动.bat」的黑窗里能看到脚本的原始报错。

**内部系统「再次执行」历史日期的任务总是失败？**
报「查询日期未生效：期望 X，表格实际为 Y」时，是日期控件没真正生效：
内部系统的日期范围是 Element 的 `el-date-editor--daterange`，它把「显示值」和
「内部模型」分开存，只写输入框只改显示、查询仍用页面旧日期。
定时任务恰好取「昨天」＝页面默认值，所以看不出问题；**任何历史日期重跑都会失败**。
2026-10-16 已修复（改为直接驱动 `ElDatePicker.emitInput` 写入 v-model，
CDP 直连与 Playwright 兜底两处都改了）。若仍失败，在账号管家里手动刷新该标签页再试。

> 顺带记一个易混点：内部系统按「昨天」取数，**产出目录名是运行日、不是数据日期**——
> 目录 `20261012` 里装的是 **10-11** 的数据（看 Excel 名 `_图片_2026-10-11-...`）。
> 手动指定数据日期时同样遵守这个口径：**目录 = 数据日期 + 1 天**。

**分类提示「API 未配置」？**
去「素材治理」页填 API 端点、模型 ID、API Key。模型必须支持看图。

**模型返回 `Expecting value: line 1 column 1`？**
说明返回的不是 JSON，通常是网关协议选错了（比如把 Anthropic 格式的中转站当 OpenAI 用）。
在 API Endpoint 里确认地址与协议匹配。

**中转站报 `No available providers`（503）？**
是账号在中转站没有可用渠道或余额，不是本工具的问题。

**分类不准？**
换更强的视觉模型，或人工把分错的图挪到正确目录——引擎会把已有目录结构反哺给规则参考。

**计划到点没跑？**
1. 工具是否还开着（关掉就不触发）
2. 计划是否处于「启用」状态
3. 执行日的星期是否包含今天
4. 「运行历史」里会留下失败原因，先看那儿

**会改原图吗？**
分类默认「复制」，完全不动原文件；只有选「移动」才会腾空原始素材目录。

## 依赖还原

仓库里**不含**依赖与运行时（体积超出 GitHub 单文件上限），clone 后按下表补齐：

| 目录 | 大小 | 还原方式 |
|---|---|---|
| `node_modules/` | ~259M | 在项目根目录执行 `npm install`（`package.json` 里只有 electron） |
| `classify-engine/runtime/` | ~390M | 放一份精简 Python 运行时到该路径；见下 |

`classify-engine/runtime/` 约定结构：

```text
classify-engine/runtime/
└── python/
    └── python.exe          # 解释器入口，主进程与各工具脚本都按这个相对路径调用
```

两种做法：

1. **直接用系统 Python**（最省事）——装好 Python 3.10+，创建目录并把解释器软链/拷贝过去：

   ```bat
   mkdir classify-engine\runtime
   mklink /J classify-engine\runtime\python "C:\Python312"
   ```

   需要装的包：`requests`、`pandas`、`openpyxl`、`playwright`、`websockets`。
   Playwright 还要执行一次 `playwright install chromium`。

2. **用嵌入式/便携版 Python**（换机器免装环境）——下载 embeddable 包解压到
   `classify-engine/runtime/python/`，再 `pip install` 上述依赖。

> Python 依赖未随仓库分发，是为了绕开 GitHub 的体积与二进制文件限制；
> 装好之后，启动器和采集脚本都按 `classify-engine/runtime/python/python.exe`
> 这个相对路径找解释器，路径一致即可。

## 打包发给别人

当前是**源码态启动器**，代码在目录里原样运行，改代码立即生效，适合自用和边改边测。

要发给别人（改代码不再生效的独立安装版），用 `electron-builder` 打包即可：
应用体积主要在 `node_modules`（约 259M，含 Electron）和 `classify-engine`（约 390M，含 Python 运行时与 Playwright）。
分发时建议剔除 `userdata/cache`（约 228M，是视觉 API 结果缓存，会自动重建）以及
`userdata/capture_plans.json` / `run_history.json` / `logs/`。
